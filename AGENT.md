# Встроенный агент phpcode

Реализация собственная: `agent/` содержит runtime и нативную панель редактора, `agentProvider/` — защищённый IPC transport к BotHub и polza.ai из main-процесса. `apply-provider.cjs` и `apply-agent.cjs` воспроизводимо переносят эти исходники в Code OSS; пользовательские VSIX для агента не требуются. Источники Cursor в реализацию не включены.

## Интерфейс и сценарии

Панель «Агент» расположена справа. Команда `phpcode.agent.open` открывает панель; ⌥⌘I на macOS переключает её видимость, отдельные вкладки чатов, новый чат, закрытие и восстановление через «История». История, выбранная модель, режим, черновик, предложения и переписка сохраняются в локальной базе workspace. После перезапуска незавершённый запрос становится остановленным.

В меню с именем провайдера пользователь выбирает BotHub / polza.ai и сохраняет отдельный API-ключ через нативное защищённое хранилище Code OSS. Ключ отсутствует в настройках и истории. Выбор модели загружает каталог `GET /models`; ID можно ввести вручную. Часть моделей выбранного провайдера может не поддерживать вызов инструментов или быть недоступной для конкретного ключа — это требует проверки реальным запросом. «Обновить модели» заново получает каталог.

Agent выполняет цикл запросов и инструментов; Ask передаёт только инструменты чтения. Поддержаны список файлов, текстовый поиск, чтение открытых несохранённых документов, добавление файлов, папок и выделения через кнопку контекста/`@`, перетаскивание файлов и папок проекта из Explorer или native file transfer, предложения полного содержимого файла и выполнение команды терминала. Длинные файлы возвращаются явными страницами до 200 строк и 20000 символов с указанием следующего диапазона (`start_line`/`end_line`), вместо молчаливого обрезания начала. Текст и вызовы инструментов поступают потоком. «Остановить» прерывает запрос и собственный выполняющийся терминал.

Предложения показываются отдельными карточками. Diff открывается в стандартном редакторе сравнения. «Применить» использует bulk edit редактора и сохраняет подтверждённую правку с обычными участниками сохранения/форматированием. В «Полуавтоматическом» и «Автоматическом» режимах новые предложения применяются и сохраняются сразу; «Ручной» ожидает нажатия «Применить». «Отменить» возвращает исходное содержимое, если файл с тех пор не менялся; последовательные версии правок одного файла можно отменять по очереди. После форматирования используется фактически сохранённое содержимое для проверки безопасной отмены. Изменения пользователя после предложения не затираются. В ручном и полуавтоматическом режимах команда ожидает отдельного разрешения с видимым полным текстом. В автоматическом режиме команды исполняются сразу, без дополнительных подтверждений. Старые сессии с автоматическими правками и отсутствующей политикой команд становятся полуавтоматическими; полный автоматический режим требует его явного выбора. Ask остаётся режимом чтения независимо от сохранённых политик.

Чтение ограничено доверенной папкой проекта; переходы через `..`, символические ссылки и известные имена файлов учётных данных исключаются. Это не универсальный поиск всех возможных секретов: пользователь выбирает отправляемый контекст. Поиск использует сервис редактора и его ignore/exclude настройки. Команды исполняются с правами пользователя согласно выбранному режиму; sandbox команд в этом этапе не реализован.

## Команды агента

Внизу редактора рядом с Output, Terminal и Ports зарегистрирована единая вкладка «Команды агента». Команды из всех чатов открытого проекта показываются в общем журнале: чат, время запуска, полный текст команды, рабочая папка, поток stdout/stderr, статус, код завершения и длительность. Команда `phpcode.agent.console.open` открывает журнал из палитры. Запуск раскрывает панель без передачи ей фокуса ввода.

Каждая команда использует скрытый одноразовый PTY с `hideFromUser`, `isFeatureTerminal` и `isTransient`. После завершения, отмены или таймаута PTY уничтожается; новые пользовательские вкладки Terminal не создаются. Это общий журнал запусков, а не постоянная интерактивная shell-сессия: команды начинают работу в корне проекта, `cd`/переменные предыдущей команды между запусками не переносятся. Последовательные операции можно объединять в одной команде. Интерактивный ввод в этой версии не поддерживается; остаётся таймаут 120 секунд.

Журнал хранится отдельно от переписки в workspace storage (`phpcode.agent.commands.v1`), восстанавливается при перезапуске, сохраняет до 100 последних записей с общим бюджетом 2 млн символов. Для каждого запуска сохраняется последняя часть вывода до 64000 символов; модель получает до 22000 символов. Ограничение явно обозначается. Незавершённая запись после перезапуска отмечается прерванной. Кнопка «Остановить» прерывает конкретную команду, а «Очистить завершённые» удаляет законченные записи без остановки работающих процессов. Закрытие чата прерывает его текущий запрос и команду, журнал остаётся доступным.

Пути в ответах агента становятся ссылками: обычные относительные/абсолютные пути внутри проекта, Markdown-ссылки и номера строк `file.php:42:3`/`file.php#L42`. Файл открывается в штатном редакторе, папка раскрывается в Explorer. URL и блоки кода не превращаются в файловые ссылки; команды из Markdown не разрешаются. При смене workspace устаревшая операция открытия не применяется к новой папке.

## Суммаризация и компактная панель

Служебные действия каждого запроса сгруппированы под свёрнутым разделом «Действия», а список файлов — под «Изменения». Ответ модели остаётся видимым. Разворачивание сохраняется при потоковом обновлении. Поле ввода содержит режим ручной, полуавтоматический, автоматический режим или Ask, модель, добавление контекста и отправку/остановку. Голосовой ввод и кнопки неподдерживаемых функций не имитируются.

Файлы и папки можно добавить выбором и drag-and-drop. Папка передаётся как ограниченный список путей (до 200), без автоматической отправки всего содержимого. Для чтения содержимого агент использует индекс и файловые инструменты. Вложение ограничено восемью элементами и открытым проектом; пути проверяются независимо от типа drag payload.

По умолчанию входной бюджет определяется окном выбранной модели из каталога выбранного провайдера (`context_length` и документированные алиасы), с резервом 10% (от 2048 до 16384 токенов) для ответа. Метаданные каталога сохраняются между запусками и обновляются перед первой отправкой. Старое значение 32k из r3 мигрирует в автоматический режим. Для неизвестного окна явно используется временный локальный бюджет 128k; доступны ручные значения и произвольный бюджет 2000–2000000 токенов, ограниченный известным окном модели. Индикатор — приблизительная консервативная оценка UTF-8, а не точное окно каждой модели. Фактические usage-счётчики провайдера показаны отдельно. На 80% бюджета перед следующим шагом автоматически выполняется дополнительный текстовый запрос той же модели: старая часть истории сворачивается в сводку целей, ограничений, решений, файлов, правок, проверок и незавершённых задач. Последний запрос пользователя и полные последние пары вызовов/результатов инструментов сохраняются. Сводка ограничена по размеру, вход суммаризатора — по UTF-8 байтам.

Сводка сохраняет завершённые выводы исследования и следующие шаги; она не требует заново перечитывать все уже изученные файлы.

Полная видимая история сохраняется отдельно от сокращённого API-контекста, включая перезапуск приложения. При ошибке или отмене суммаризации исходный контекст не подменяется. Один слишком большой новый запрос/вложение не сокращается молча: требуется уменьшить вложения, изменить бюджет или создать новый чат. Суммаризация сама использует API и может оплачиваться; она включена в статистику запросов и токенов.

Один запуск теперь допускает до 100 шагов модели. Повторяющиеся чтения и поиски с неизменными результатами вызывают подсказку о необходимости перейти к реализации; шесть таких шагов подряд останавливают запуск с отдельным сообщением. Любая мутация сбрасывает наблюдения. Ограничения шагов, повторов, объёма ответа и протокола показываются отдельно от сетевых ошибок; для лимита шагов и повторов есть кнопка продолжения с сохранённым контекстом.

## Локальный индекс проекта

`codeIndexService.ts` строит постоянный индекс внутри профиля workspace (`User/workspaceStorage/<id>/phpcode/code-index-v1.json`), без сетевых запросов и embeddings. Учитываются `.gitignore`/настройки исключений редактора и корневой `.phpcodeignore` с упорядоченными glob-правилами и `!`-исключениями. Генерируемые каталоги, зависимости, бинарные/крупные файлы, известные имена секретов и переходы по символическим ссылкам исключаются. Автоматическая индексация строже ручного прикрепления файла.

Код разбивается на фрагменты до 80 строк и 3000 символов с перекрытием. Инвертированный индекс ранжирует совпадения по словам кода, camelCase/snake_case, имени файла/пути и объявлениям символов. Это лексический поиск, не обещание семантического понимания запросов. Инструмент `search_code` доступен в Agent и Ask; возвращаются до шести результатов с путями/строками и общим ограничением вывода 12000 символов. Для остальных файлов сохраняются обычные инструменты поиска.

Файловые события обновляют изменённые записи; неизменившиеся файлы не перечитываются целиком. Несохранённые изменения существующих документов участвуют в живом поиске, но не записываются в дисковый индекс. Кеш проверяется при запуске и восстанавливается по версии, корню проекта и отпечаткам файлов. В панели показаны состояние и число файлов, доступны детали и пересоздание.

Защитные пределы первой версии: 3000 файлов, 200 КБ на файл, 20 МБ исходного текста и 20000 фрагментов. При достижении предела интерфейс показывает частичный индекс. Обычный поиск остаётся доступным. Это позволяет не выдавать ограниченный индекс за полный индекс большой кодовой базы.

## Кеширование и расход токенов

Инструкции и схема инструментов сохраняют стабильный префикс; динамические состояния редактора добавляются в конец нового сообщения. История не переписывается ради кеша. Для ID моделей `claude-*` и `anthropic/claude-*` wire-адаптер добавляет до двух текстовых контрольных точек `cache_control: {type: 'ephemeral'}`: системное сообщение и последнее пользовательское. По BotHub это TTL 5 минут. Настройка «Кеш Claude (5 минут)» отключает эти явные метки; она не отключает автоматический кеш других провайдеров.

Для остальных моделей отдельные метки не отправляются. Согласно [документации BotHub](https://bothub.chat/api/documentation/ru/prompt-caching), кеш OpenAI, Grok, DeepSeek и ряда других моделей автоматический и зависит от доступности, минимального размера и совпадения префикса. Запись кеша Claude может стоить дороже обычного ввода; повторное чтение дешевле. Тарифы различаются по модели, тарифу/организации и могут меняться; приложение не подставляет фиксированный процент экономии.

Запрос включает `stream_options.include_usage`. Панель суммирует только счётчики, явно вернувшиеся от провайдера: входные/выходные токены, `cached_tokens`, `cache_write_tokens`. Если счётчик отсутствует, показано «—»; отдельно указано количество запросов, по которым получена статистика. Сокращение цены, деньги и фактические попадания реального аккаунта в этом тестовом прогоне не измерялись. Кеширование не устраняет оплату нового вывода и рассуждений модели.

## Проверка

`verify-agent.cjs` запускает отдельный профиль и подменяет HTTP только внутри собственного тестового main-процесса. Он проверяет каталог моделей, потоковый цикл чтение → предложение → ответ, отсутствие записи до Apply, нативный diff, применение/отмену, разрешения ручного/полуавтоматического режима, выполнение команд без подтверждения в автоматическом режиме, единый журнал stdout/stderr/exit code, остановку команды и восстановление журнала, исключение `.env`, Ask, Stop, восстановление закрытого чата, историю после перезапуска, явные Claude cache-метки, их отключение и отображение токенов кеша; индекс проверяется на поиск фрагментов, обновление после сохранения, несохранённый текст без записи в индекс и исключение ignore/секретов/символических ссылок. Реальный ключ и баланс BotHub в этом прогоне не используются.

Узкие тесты runtime и transport: `./run.sh bash scripts/test.sh --run src/vs/workbench/contrib/phpcode/test/common/runtime.test.ts --run src/vs/workbench/contrib/phpcode/test/common/providerRequest.test.ts --run src/vs/workbench/contrib/phpcode/test/common/codeIndex.test.ts --run src/vs/platform/phpcodeProvider/test/electron-main/provider.test.ts --grep phpcode`. Они проверяют раздельные chunks инструментов, корректный transcript, неполные ответы, отмену, ограничения контекста/вывода, ошибки провайдера, UTF-8, ограничения размера и изоляцию запросов/событий разных окон.

Для нового исходного checkout: применить существующие product/UI/build/removal overlays, затем `node apply-provider.cjs` и `node apply-agent.cjs`; запустить build-fast, целевые проверки и обычный `gulp vscode-darwin-arm64`.

## Границы текущего этапа

Это рабочая первая интеграция основных сценариев агента, а не полная функциональная эквивалентность Cursor. В неё не входят векторный семантический поиск, MCP-инструменты, браузер агента, Plan, автоматические checkpoints всего проекта, фоновые cloud-агенты и inline Tab completion. Работа в Dev Container проверяется в реальном удалённом workspace с Linux ARM64/amd64: файлы, правки, shell, рабочая папка и remoteEnv. SSH пока не проверен; локальный терминальный запуск проверен на macOS. Подробности — в `DEVCONTAINERS.md`. Нельзя выдавать эти возможности за реализованные на основании сходства интерфейса.

Исследование установленного Cursor и границы наблюдений зафиксированы в `../CURSOR_ARCHITECTURE.md`.


## Субагенты и индикаторы работы

Agent умеет делегировать независимые задачи через `run_subagent`: отдельный контекст, роли explore/shell/general, до трёх параллельных работников. Вложенные свёрнутые карточки показывают модель, состояние, длительность и действия. Общая остановка отменяет дочерние запросы. Режимы правок и подтверждений сохраняются, команды сериализованы; истории субагентов сохраняются вместе с чатом. Подробнее: [SUBAGENTS.md](docs/SUBAGENTS.md).


## Выбор провайдера

BotHub и polza.ai поддерживаются встроенным транспортом; провайдер и последняя модель каждого сервиса сохраняются для чата. Старые чаты используют BotHub. Субагенты и суммаризация наследуют выбранное подключение. Ключи и каталоги раздельные. Подробнее: [PROVIDERS.md](docs/PROVIDERS.md).


## Неинтерактивные команды

Скрытые терминалы агента получают `GIT_PAGER=cat`, `PAGER=cat`, `MANPAGER=cat`, `SYSTEMD_PAGER=cat` и `GIT_TERMINAL_PROMPT=0`, включая запуск в Dev Container. Это предотвращает остановку Git на `--More--` / `(END)` в ожидании клавиши. Обычные терминалы и Git-конфигурация пользователя не меняются. PowerShell запускается с `-NonInteractive`. Для других программ агент должен передавать соответствующие неинтерактивные флаги.

Проверка: `PHPCODE_TERMINAL_SMOKE=1 PHPCODE_PACKAGED_EXECUTABLE=/absolute/path/to/phpcode node verify-agent.cjs` запускает Git в настоящем скрытом PTY с принудительным пейджером-ловушкой и проверяет, что он не запускался, вывод вернулся и код завершения равен 0. Используются отдельный тестовый Git-репозиторий и подставной ответ API.


## Действия и время ответа

Diff и отмена правок показываются иконками с подсказками. Под каждым ответом при наведении или фокусе клавиатуры появляются копирование исходного текста ответа и локальные дата/время. Время первого фрагмента нового ответа сохраняется в истории и не меняется после перезапуска. Для старых сообщений без метаданных показана «Дата не сохранена». Буфер обмена получает только текст ответа.

`PHPCODE_DESIGN_SMOKE=1 PHPCODE_PACKAGED_EXECUTABLE=/absolute/path/to/phpcode node verify-agent.cjs` проверяет hover, копирование через нативный clipboard, сохранение времени, Diff и отмену. Исходное содержимое буфера обмена восстанавливается после проверки.
