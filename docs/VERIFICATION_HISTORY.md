# История локальной проверки до переносимой сборки

Это архив предыдущего этапа. Пути и команды ниже относятся к прежнему расположению каталогов на macOS. Актуальные команды — в [BUILDING.md](BUILDING.md).

# Сборочный профиль phpcode

Исходная база: `../phpcode-oss`, официальный тег Code OSS `1.146.0`. `product-overrides.json` содержит собственное имя, каталоги данных и серверов и адреса каталога Open VSX. Применение: `node apply-product.cjs ../phpcode-oss`. Повторное применение даёт тот же результат; существующие поля product.json, не указанные в профиле, сохраняются.

Собрано и проверено самостоятельное приложение `../VSCode-darwin-arm64/phpcode.app`. Это первая база редактора Code OSS с именем phpcode, темой Dracula, иконками проекта, вкладками и плавной прокруткой. Встроен собственный агент BotHub: сессии, история, контекст файлов, потоковые ответы, цикл инструментов, diff, подтверждение команд, локальный индекс проекта и поддержка prompt cache Claude со статистикой токенов, автоматическая суммаризация, ручной/полуавтоматический/автоматический режимы, общая панель команд агента, ссылки на файлы/строки и контекст файлов/папок через drag-and-drop. Встроен клиент MySQL/MariaDB и PostgreSQL: сохранённые подключения, дерево схем/таблиц, редактор данных и выполнение SQL-файлов; описание и ограничения — в `DATABASE.md`. Подробности и ограничения агента — в `AGENT.md`. Встроены Dev Containers с удалённым workspace, автоматическим предложением и отдельной кнопкой запуска; описание, проверенные платформы и ограничения — в `DEVCONTAINERS.md`. SSH и расширенный PHP-стек пока не прошли продуктовую интеграцию.

Проверенная локальная база: коммит `69047191fc427f2f92828279aae1d90d8eeda7ab`, тег `1.146.0`. `.nvmrc` требует Node `24.22.1`, `packageManager` — `pnpm@12.16.0`. Обе версии установлены локально в `../tools/phpcode-build`, контрольная сумма архива Node сверена с официальным SHASUMS256.txt. Обёртка `run.sh` выбирает эти инструменты, не меняя системную версию Node.

`node apply-ui.cjs ../phpcode-oss` добавляет тему Dracula и SVG-иконки в существующий пакет встроенных тем и регистрирует продуктовые значения настроек в ядре workbench. Пользователь по-прежнему может переопределить их в settings.json. Вкладки включены, режим временного предпросмотра по умолчанию выключен, прокрутка списков/редактора/терминала плавная. Изменение применяется повторно без дублирования импортов и тем.

Также исключены регистрации панелей отладки, Debug Console и Problems. Сервисы диагностики и extension-host API сохранены. Полная очистка команд отладки/задач и ограничение multi-root ещё требуют следующего этапа: эта сборка пока не реализует все исключения интерфейса из спецификации.

`node apply-build.cjs ../phpcode-oss` добавляет проверку `enableBuiltinCopilot` в упаковщик: для phpcode встроенный Copilot не включается в пакет и не выполняется подготовка его CLI SDK. Исходный OSS-упаковщик требовал каталог SDK, отсутствующий в собранном пакете; без этой продуктовой настройки финальная упаковка завершалась ошибкой. Зависимости `@github/copilot*` и дополнительные файлы runtime также исключаются из приложения; зависимости исходного дерева сохраняются для воспроизводимой установки по upstream lockfile.

`node apply-copilot-removal.cjs ../phpcode-oss` отключает штатного провайдера и его предзапуск, предложения авторизации и onboarding, убирает его команды из меню и палитры и настройки из интерфейса и документа значений по умолчанию. Сканер встроенных расширений также пропускает Copilot, включая dev-запуск. Обязательная структура `defaultChatAgent` сохранена с пустыми значениями из `disabled-agent-config.json`: общие API редактора ожидают эту структуру, даже когда провайдер отсутствует. Внутренние идентификаторы и схемы настроек остаются для совместимости; это не глобальное переименование исходного кода и не подключение BotHub.

Команды из каталога `phpcode-product`:

```sh
node apply-product.cjs ../phpcode-oss
node apply-ui.cjs ../phpcode-oss
node apply-build.cjs ../phpcode-oss
node apply-copilot-removal.cjs ../phpcode-oss
node apply-provider.cjs ../phpcode-oss
node apply-agent.cjs ../phpcode-oss
node apply-database.cjs ../phpcode-oss
node apply-devcontainers.cjs ../phpcode-oss
./run.sh pnpm install --frozen-lockfile --store-dir ../tools/phpcode-build/pnpm-store
./run.sh pnpm run build-fast --client-only
./run.sh pnpm run gulp transpile-extensions compile-extension-media
./run.sh pnpm run electron
./run.sh node ../phpcode-product/verify-base.cjs
./run.sh node ../phpcode-product/verify-visible-branding.cjs
./run.sh node ../phpcode-product/verify-agent.cjs
./run.sh pnpm run gulp vscode-darwin-arm64
PHPCODE_PACKAGED_EXECUTABLE="$PWD/../VSCode-darwin-arm64/phpcode.app/Contents/MacOS/phpcode" ./run.sh node ../phpcode-product/verify-base.cjs
```

`verify-base.cjs` использует отдельный временный профиль и собственный тестовый проект. Проверяются два постоянных таба, редактирование документа, создание двух терминалов, активация Git, установка и активация собственного локального VSIX, наличие команд поиска/настроек и значения темы/иконок/прокрутки. Проверки прошли как для dev-запуска, так и для упакованного приложения. Это не функциональный прогон всех возможностей VS Code: например, восстановление документов после перезапуска и визуальная плавность прокрутки ещё не измерялись. Дополнительно проверяется отсутствие расширения Copilot, выключенные продуктовые значения AI-настроек и отсутствие упоминаний провайдера в документе настроек по умолчанию. `verify-visible-branding.cjs` проверяет нативные меню, видимый текст/подсказки, значок, палитру команд и открытый терминал на профиле, где пользовательские настройки ранее включали встроенный AI. Результат упакованной сборки сохранён в `verification-result.json`.

Сборка для macOS Apple Silicon локальная, без Developer ID и notarization. Её установочный образ находится в `release/phpcode-CodeOSS-1.146.0-arm64-r11.dmg`.

Code OSS сохраняет механизм расширений и привычные компоненты редактора. Каталог Open VSX не идентичен Microsoft Marketplace; совместимость конкретных расширений проверяется отдельно. Запуск CLI devcontainers сам по себе не является полноценной реализацией удалённого редактора.
